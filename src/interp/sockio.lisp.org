** Hosting the socket layer on SBCL

The seventeen =defentry= bindings in the block below divide along
the same line drawn in =cfuns.lisp.pamphlet=: most are genuinely
foreign, a few only look it.

Twelve --- =open_server=, the =sock_*= transfer calls,
=server_switch=, =flush_stdout=, =sock_send_signal= and
=print_line= --- are the real client/server socket layer that the
HyperDoc browser and the graphical front end use to talk to the engine.
They cross into C and have no meaning without the server. Because this
port targets a console =AXIOMsys= first and defers HyperDoc, we do
not bind them on SBCL; we install /stubs/ that raise a clear error
if anything calls them. The console interpreter never does --- recall
that =spad-save= sets =$SpadServer= to nil --- so the stubs
merely make the absence explicit instead of failing later with an
obscure ``undefined function''. When HyperDoc is eventually built these
become real =sb-alien= routines against the socket C, which is the
one place in the whole port where =sb-alien= is genuinely
warranted.

The other three are not sockets at all. =plus_infinity=,
=minus_infinity= and =NANQ= return IEEE double values that the
=Float= domain needs and that GCL happened to obtain through C.
SBCL exposes them directly: the two infinities are constants, and a
quiet NaN is the result of an invalid operation evaluated under masked
float traps. We reimplement these in Lisp, exactly as the hashes were
--- they are not foreign, only historically routed through C.

#+:sbcl
(progn
  ;; IEEE float edge values: not foreign, reimplemented in Lisp (see prose).
  ;; The ftype declaim is load-bearing, not decoration. Each body returns
  ;; a literal infinity, so SBCL's type derivation narrows the result to a
  ;; singleton -- plus_infinity to (double-float +inf +inf) -- and then
  ;; folds NANQ's (- +inf +inf) to the *finite* identity 0.0d0, deriving
  ;; NANQ :: (member 0.0d0). The function genuinely returns a NaN, so when
  ;; sockio.fasl is loaded the value violates that derived ftype and the
  ;; whole build-interpsys aborts (observed). Declaring the return type as
  ;; plain double-float -- which includes infinities and NaNs -- blocks the
  ;; bogus narrowing while staying true.
  (declaim (ftype (function () double-float)
                  plus_infinity minus_infinity NANQ))
  (defun plus_infinity  () sb-ext:double-float-positive-infinity)
  (defun minus_infinity () sb-ext:double-float-negative-infinity)
  ;; NANQ builds a quiet NaN from its bit pattern rather than computing
  ;; (- +inf +inf). The arithmetic form is wrong twice over on a compiling
  ;; host: with-float-traps-masked only masks at RUN time, but SBCL
  ;; constant-folds the subtraction at COMPILE time with traps live, so
  ;; merely compiling sockio raised FLOATING-POINT-OVERFLOW (observed).
  ;; make-double-float assembles the IEEE-754 quiet-NaN double directly --
  ;; sign 0, exponent all ones, mantissa MSB set, i.e. #x7FF8000000000000 --
  ;; with no float operation to fold or trap.
  (defun NANQ ()
    (sb-kernel:make-double-float #x7FF80000 0))
  ;; HyperDoc/graphics sockets: foreign, stubbed until the server is built.
  ;; The console AXIOMsys never calls these ($SpadServer is nil); the stub
  ;; turns an accidental call into a clear message instead of a crash.
  ;; No-op (return 0) rather than error: the socket/HyperDoc server is not
  ;; built into this SBCL image, but batch regression `draw` calls the send
  ;; primitives expecting a status int. Erroring crashed every draw test;
  ;; GCL's real layer simply returned a status when no viewport manager was
  ;; listening. Returning 0 lets the graph build and the viewport object be
  ;; returned without a live viewman. (Full socket layer is future work, as
  ;; in fricas/open-axiom which build the server.)
  (macrolet ((stub (name)
               `(defun ,name (&rest args)
                  (declare (ignore args))
                  0)))
    (stub open_server)          (stub sock_get_int)
    (stub sock_send_int)        (stub sock_get_string_buf)
    (stub sock_send_string_len) (stub sock_get_float)
    (stub sock_send_float)      (stub sock_send_wakeup)
    (stub server_switch)        (stub flush_stdout)
    (stub sock_send_signal)     (stub print_line)))
