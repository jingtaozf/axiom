* Line Classification Algorithm

Only lines in =PROSE= state are eligible for cleanup.

#+begin_example
state = PROSE
for each line:
  if line == "#+begin_src"        → state = SRC_BLOCK;  skip
  if line == "#+end_src"          → state = PROSE;       skip
  if line == "#+begin_example"    → state = EXAMPLE;     skip
  if line == "#+end_example"      → state = PROSE;        skip
  if line == "#+begin_quote"      → state = QUOTE;        skip
  if line == "#+end_quote"        → state = PROSE;        skip
  if line == "#+NAME:"            → skip (chunk marker)
  if state == PROSE               → eligible for cleanup
  else                            → skip
#+end_example

* Tangled-Source Invariant

=tanglec= / =orgtangle= extracts source by recognizing only:

1. =\begin{chunk}{name}= (from =#+NAME:= + =#+begin_src=)
2. =\end{chunk}= (from =#+end_src=)
3. =\getchunk{name}= (from =<<name>>=)

Everything else is ignored by the tangle algorithm.

** Verification per phase

1. Snapshot all tangled source files before phase
2. Run phase
3. Re-tangle, diff against baseline — zero diffs required
4. If any source file changes: STOP and fix

* Existing Tool Research

** Pandoc (v2.14.1 installed)

=pandoc -f latex -t org= converts standard LaTeX to org.

*** What pandoc handles well

| LaTeX construct    | Org output                          | Quality |
|--------------------+-------------------------------------+---------|
| \section{X}        | * X + :PROPERTIES: :CUSTOM_ID:      | good    |
| *X*         | *X*                                 | good    |
| /X/           | /X/                                 | good    |
| \begin{itemize}    | - item                              | good    |
| \begin{enumerate}  | 1. item                             | good    |
| $...$ math         | \(...\) (org math)                  | good    |
| \begin{equation}   | \[...\]                             | good    |
| \begin{tabular}    | \| col \| org table                 | good    |
| \label{} / \ref{}  | :CUSTOM_ID: / [[#id]]               | good    |
| \footnote{}        | [fn:N]                              | good    |
| \includegraphics{} | [[file:...]]                         | good    |
| \title / \author   | #+title: / #+author:                | good    |

*** What pandoc CANNOT handle

| Issue                        | Impact                  | Workaround             |
|------------------------------+-------------------------+------------------------|
| \documentclass preamble      | parse error             | strip first            |
| Custom macros (\pagehead...) | silently dropped        | use +raw_tex extension |
| [cite:@X]                     | passed through raw      | post-process           |
| \index{X}                    | silently dropped        | post-process           |
| \begin{chunk}...end{chunk}   | not recognized          | post-process           |
| Old-style *X*            | works in pandoc 2.14    | ok                     |
| Axiom macros (\spad etc)     | dropped without raw_tex | Lua filter or post-proc|

*** Pandoc pipeline: =raw_tex= + Lua filter

With =-f latex+raw_tex=, unknown macros pass through as raw LaTeX.
A Lua filter can then convert them to org-native:

#+begin_example
pandoc -f latex+raw_tex -t org --wrap=none \
  --lua-filter=axiom.lua input.tex -o output.org
#+end_example

Test results (partial — Lua filter needs more work):

| Macro              | raw_tex output (before filter) | After Lua filter      |
|--------------------+--------------------------------+-----------------------|
| \spad{code}        | \spad{code} (raw)              | =code=                |
| \pagehead{N}{A}    | \pagehead{N}{A} (raw)          | (not intercepted yet) |
| \pageto{N}{A}      | \pageto{N}{A} (raw)            | inline only works     |
| # calls: fn -> target | \calls{fn}{target} (raw)       | (not intercepted yet) |
| \begin{chunk}...   | broken output                  | partial               |

*** Pandoc limitations for our use case

1. Pandoc parses entire file as LaTeX — our files are org with embedded LaTeX
   in prose. Pandoc cannot parse the org-native parts (#+NAME:, #+begin_src).
2. Pre-processing needed to extract prose sections, feed to pandoc, then
   reassemble with the untouched src blocks.
3. The =+raw_tex= approach preserves content but the Lua filter approach
   requires intercepting EVERY custom macro — fragile for 1500+ unique cmds.

** Recommendation

Pandoc is useful for the STANDARD LaTeX subset (headings, bold, lists, tables,
math, footnotes, cross-refs) but CANNOT handle:

1. Axiom-specific macros (\pagehead, \pageto, \spad, \calls, \usesdollar, etc.)
2. Files that mix org-native constructs with embedded LaTeX
3. \index{} entries (silently dropped without +raw_tex)

** Proposed approach: Pandoc + Python hybrid

| Step | Tool   | Handles                                    |
|------+--------+--------------------------------------------|
|    1 | Python | Strip LaTeX preamble (lines 1-11)           |
|    2 | Python | Extract prose sections (outside src blocks) |
|    3 | Pandoc | Convert standard LaTeX → org (bold, list, table, math, heading) |
|    4 | Python | Convert Axiom macros → org (pagehead, calls, etc.) |
|    5 | Python | Reassemble: converted prose + untouched src blocks |
|    6 | Python | Post-process: \index → #+INDEX:, \cite → [cite:@X] |

Alternative: Skip pandoc entirely, use Python for everything.
The standard LaTeX patterns are regular enough for regex conversion.
This avoids the complexity of the pandoc pipeline (extract prose → feed
to pandoc → reassemble) and gives us full control over every conversion.

Pandoc is most valuable for:
- Tables (tabular → org table) — tricky regex
- Math ($...$ → \(...\)) — pandoc handles correctly
- Section headings with \label{} trailing — pandoc creates property drawers

For everything else, regex is simpler and more predictable.
