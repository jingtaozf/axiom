* The key finding: untanglec is NOT lossless at HEAD

The migration had two layers. Layer 1 (=01942865=, phases 1–3) claimed
a byte-exact roundtrip. Layer 2 — the later "org-native cleanup"
series (=cde252c0= + phases 8–14) — rewrote LaTeX prose into org markup
*one-way*. Measured against the daly base:

#+begin_example
bookvol1 (pure doc, no SBCL code change):
  untanglec(HEAD.org) is 18 KB SMALLER than daly base.pamphlet
  \pagenumbering / \mainmatter dropped; {\bf X}->*X*; {\sl X}->/X/;
  {\tt X}-> =X= ; itemize-> org list  — none reversed
#+end_example

⇒ "run untanglec to get daly pamphlets back" is *false*. The true
revert must restore base =.pamphlet= from git, then port the SBCL code
changes in.

* The revert engine (proven)

Insight: *inside a chunk = code* (identical form in pamphlet and org);
*outside a chunk = prose* (where org cleanup diverged). Diffing only
=\begin{chunk}…\end{chunk}= interiors isolates the SBCL code delta from
prose noise. Full byte-mode (=LC_ALL=C=) scan over all 1048 migrated
files:

| Class | Count | Handling |
|-------+-------+----------|
| *CLEAN* (zero chunk-code delta) | *1010* | =git checkout 7e11a37a -- F.pamphlet= + =git rm F.org= — fully automatic, zero risk |
| *CODE-CHANGED source* | *30* | restore base + *selectively* port SBCL hunks |
| *CODE-CHANGED infra* (Makefile.org family, lsp/Makefile.org) | *8* | restore base + reapply SBCL hunks (lsp/Makefile.org has none — pure org-wiring) |

Caution — some book chunks interleave SBCL and org-wiring in the *same*
file, e.g. =bookvol10.org=:

#+begin_example
(in-package (quote boot)) -> (in-package "BOOT")     <- SBCL: KEEP
${IN}/%.pamphlet -> ${IN}/%.org                       <- org-wiring: DROP
${TANGLE} ... .pamphlet -> srctangle ... .org         <- org-wiring: DROP
grep 'begin{chunk}{category }' -> grep '^#+NAME: '     <- org-wiring: DROP
#+end_example

base-restore drops the org-wiring automatically; only the SBCL lines
need re-adding. Never blindly apply the whole chunk-diff.

* Phased execution

Phases are commits on a working branch. CI cannot be green until the
build system is repointed, so the *green checkpoints are after B, C and
E* — Phase A's intermediate red on the branch is expected, not a
failure.

** Phase 0 — baseline anchor (read-only)
Build AXIOMsys on the current org tree and run the 5-shard regression;
*record the green count* (the SBCL port reported 519/525). Every later
phase must match this number — it is the proof that SBCL fixes survive.

** Phase A — 1010 CLEAN files (automatic batch)
Script: for each, =git checkout 7e11a37a -- F.pamphlet= ; =git rm F.org=.
Gate: code is byte-identical to daly; spot-check =tanglec=. CI is red
here (build still points at .org) — fixed in B.

  =orgtangle= rules).
